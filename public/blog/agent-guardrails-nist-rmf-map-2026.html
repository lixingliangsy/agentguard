Agent guardrails mapped to the NIST AI RMF

Agent guardrails are the input filters, tool permissions and output checks that constrain what an autonomous agent can do before, during and after a tool call. The NIST AI Risk Management Framework gives them a vocabulary: Govern, Map, Measure, Manage.

Key takeaways

  • Govern decides who may enable a tool; Map inventories what the agent can reach; Measure tests it; Manage responds when it misbehaves.
  • Rate each tool by blast radius — read-only is cheaper to allow than write, and write is cheaper than an irreversible external action.
  • Guardrails reduce blast radius. They do not make an agent safe, and they are decision-support rather than a certification.

Mapping the four functions

  • Govern. Who approves a new tool, and what does the approval record contain?
  • Map. An inventory of tools, the data each one can touch, and the agent's trust boundary.
  • Measure. Testing the agent against the permissions you think it has, including adversarial prompts.
  • Manage. Monitoring, escalation and the kill switch for when a tool is abused.

Rating a tool call

AgentAegis reviews an agent's prompt and tool list and rates the risk of each tool call, then suggests input and output filters. A read-only lookup is a different risk class from a tool that sends email, moves money or deletes records — rating them the same way is how teams end up with a guardrail that looks thorough and stops nothing.

What the output gives you

A per-tool risk rating, suggested input/output filters, and an EU AI Act mapping you can hand to whoever owns governance. The point is that the review is repeatable: re-run it when the tool list changes, not only at launch.

Frequently asked questions

Do guardrails make an agent safe?

No. They constrain the blast radius of a mistake. A determined attacker, a mis-scoped tool or a bad prompt can still cause harm inside the boundary you allowed.

What do we need to run a review?

The agent's system prompt and its tool list. That is enough to rate calls and suggest filters.

Is the EU AI Act mapping legal advice?

No. It is a mapping to help you find the right obligations. Classifying your system and meeting the obligations still needs a qualified reviewer.

How often should we re-run it?

Whenever the tool list, the system prompt or the data a tool can reach changes.

Does it test the agent at runtime?

It reviews the prompt and tool configuration. Runtime monitoring is a separate layer you still need.

What if a tool is genuinely high risk?

Require an approval step, narrow its parameters, and log every invocation. High-risk tools usually need a human in the loop rather than a filter.
